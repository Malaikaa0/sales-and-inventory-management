# N3 — Purchase validation failure returns 200, not 4xx

| Field | Value |
| --- | --- |
| Component | `POST /transactions/new-purchase/` (`PurchaseFormMixin`, Django `CreateView`) |
| Severity | Minor |
| Priority | P3 |
| Status | Open |
| GitHub Issue | [#3](https://github.com/Malaikaa0/sales-and-inventory-management/issues/3) |
| Breaks | No requirement directly; API-level weakness (a client cannot tell a rejection from the status code) |
| Found by | `test_purchase.py` (Member 2) |

## Steps to reproduce

1. Log in as `manager`.
2. POST `/transactions/new-purchase/` with `quantity=0` and otherwise valid fields.

## Expected

For an API client: a 4xx status (for example 400) so the rejection is detectable.

## Actual

200 with the form shown again and the error under the quantity field. Nothing is saved (stock unchanged). This is the normal Django HTML form pattern.

## Evidence

- Test: `tests/team/api/test_purchase.py::test_purchase_validation_failure_returns_200_N3` (passes by design: it records the observed 200 and checks stock is unchanged)
- `reports/api/results-baseline.xml` line 14: `<testcase classname="tests.team.api.test_purchase" name="test_purchase_validation_failure_returns_200_N3" .../>` (passed)

## Triage decision

Deferred / won't fix for this release. The endpoint is a browser form, not a JSON API, and no data is corrupted. Recorded as an endpoint weakness together with the void endpoint (same pattern).
