# N7 — Till accepts 150% tax and charges 100% without warning

| Field | Value |
| --- | --- |
| Component | Point of sale page (`static/js/pos.js:93`, `transactions/templates/transactions/sale_create.html:14`) |
| Severity | Major |
| Priority | P2 |
| Status | Open |
| GitHub Issue | [#8](https://github.com/Malaikaa0/sales-and-inventory-management/issues/8) |
| Breaks | BR3 (tax is 0 to 100 percent; out-of-range input is rejected); UC-M2-2 exception flow E3 |
| Found by | Playwright E2E test `test_uc_m2_2_exc3_tax_out_of_range_rejected` (Member 2) |

## Steps to reproduce

1. Log in as `cashier` and open **New sale**.
2. Add a product priced 10.00 and choose a customer.
3. Type `150` in **Tax %** and `100` in **Amount paid**.
4. Click **Complete sale**.

## Expected

The sale is not saved. The till shows an error such as "Tax must be between 0 and 100 percent." and the cashier can correct the value. Stock is unchanged.

## Actual

The sale is saved and the "Sale completed" dialog appears with sale total **Ksh 20.00**, which is 100% tax, while the Tax field still shows 150. No warning is shown. The amount charged differs from what the cashier entered.

Cause: the form has `novalidate`, so the browser's `max="100"` check is skipped. `totals()` then clamps the rate with `Math.min(100, Math.max(0, …))` and sends 100 to the server, which accepts it as valid. The server-side range check (`services.py:75-76`) never sees the 150. The redeem field is clamped the same way (`pos.js:91`).

## Evidence

- Test: `tests/team/e2e/test_e2e_m2_use_cases.py::test_uc_m2_2_exc3_tax_out_of_range_rejected`
- `reports/e2e/run-m2.txt` line 34: `AssertionError: Locator expected to be visible` (no error shown)
- Same file, lines 131–138: dialog "Sale completed", receipt `IMS000122`, sale total `Ksh 20.00`

## Triage decision

Fix. Do not clamp silently. Show the error and block submission when tax (or redeem) is out of range, or send the typed value and show the server's 400 message. Major because money is charged that differs from what was entered, with no warning. P2: needs a cashier typing error to happen, and the server limit still caps the tax at 100%.
