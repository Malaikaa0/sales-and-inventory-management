# N8 — Logged-out till shows "Unexpected server response." instead of a sign-in prompt

| Field | Value |
| --- | --- |
| Component | Point of sale page (`static/js/pos.js:268-269`) with `role_required` redirect (`accounts/permissions.py:122-123`) |
| Severity | Minor |
| Priority | P3 |
| Status | Open |
| GitHub Issue | [#9](https://github.com/Malaikaa0/sales-and-inventory-management/issues/9) |
| Breaks | BR4 usability (UC-M2-2 exception flow E5: the cashier is told to sign in again) |
| Found by | Playwright E2E test `test_uc_m2_2_exc5_session_expired` (Member 2) |

## Steps to reproduce

1. Log in as `cashier`, open **New sale**, add a product, choose a customer, and click **Exact**.
2. In another tab of the same browser, click **Sign out** (or let the session expire).
3. Back on the till, click **Complete sale**.

## Expected

No sale is saved, and the cashier is taken to the login page or told that the session has ended and to sign in again.

## Actual

No sale is saved, which is correct. But the till shows only **"Unexpected server response."** and stays on the page. The server answers the POST with a 302 to the login page. `fetch` follows it and gets the login HTML, and `response.json()` fails, so the generic message is shown. The cashier is not told what to do.

## Evidence

- Test: `tests/team/e2e/test_e2e_m2_use_cases.py::test_uc_m2_2_exc5_session_expired`
- `reports/e2e/run-m2.txt` line 149: `AssertionError: Cashier sees: 'Unexpected server response.' on http://127.0.0.1:38535/transactions/new-sale/`

## Triage decision

Fix, low priority. In `pos.js`, detect a redirect to the login page (`response.redirected` and a URL containing `/accounts/login/`) and either reload to the login page or show "Your session has ended. Sign in again." Alternatively, return 401 JSON for AJAX requests. No data risk.
